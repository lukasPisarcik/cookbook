# Internationalization (i18n)

Applies to: any user-facing string in `*.svelte` or `*.ts` files. Only present when i18n was enabled at scaffold time.

## Pattern

Strings live in `src/lib/dictionary/dictionary.ts`. Each key maps to a `Record<MeetingLanguageCode, string>`:

```ts
// src/lib/dictionary/dictionary.ts
export const dictionary = {
	patientCount: {
		en_us: 'Patients',
		es_es: 'Pacientes'
	}
};
```

The reactive wrapper in `src/lib/dictionary/dictionary.svelte.ts` exposes `d.patientCount` (a `$derived` rune that follows `langStore.locale`):

```svelte
<script lang="ts">
	import { d } from '$lib';
</script>

<h2>{d.patientCount}</h2>
```

## Adding a new key

1. Add the key + a record per supported locale to `dictionary.ts`.
2. Add a `$derived` line in `dictionary.svelte.ts`:

   ```ts
   patientCount = $derived(dictionary.patientCount[lang.actual]);
   ```

3. Use `d.patientCount` in your component.

TypeScript will complain if a locale is missing — keep all locales in sync.

## Adding a new language

1. Add the code (e.g. `'fr_fr'`) to the `MeetingLanguageCode` enum in `src/lib/schemas/schemas.ts`.
2. Add a `LanguageConfigEntry` (label, flag, dir) to `languageConfig` in `src/lib/stores/langStore.svelte.ts`.
3. Add an entry per existing dictionary key in `dictionary.ts` (TypeScript will error on every key until done).
4. Verify in the browser by selecting the new language from the Header dropdown.

## RTL support

Languages with `dir: 'rtl'` (Arabic, Hebrew) automatically apply `dir="rtl"` to `<html>` via `langStore.applyLanguage()`. Use Tailwind's RTL utilities (`rtl:` prefix) in components when you need direction-aware layout.

## Server-side translation

For HTTP responses or webhook replies that need a translated string, use `getRequestTranslator(request)` from `$lib/server/utils/i18n` — it picks a locale from the `Accept-Language` header and returns a typed `t(key)` function.
